## 4. 分项测评

### 4.1 流程与引导 · **4.5 / 5**

**优点**

- 二十画像全部到达结局，主循环（信纸 → 日常 → 睡觉 → 过天 → 觉醒/结局）闭环成立。
- D1 未打招呼不能睡觉：H1、R1 故意跳流程时被正确拦截（`她还不知道该怎么叫你。先跟她打个招呼。`）。
- **赶走线 B1 已验证**：D6 `ending_bad_early`，notes `赶走=true`，用时 13.9s，比全量局短近一半。
- D7–D9 不再出现「还有话没说完」强推 beat，流程摩擦较第二轮明显降低。

**待观察**

- E1 手动划页后仍出现 `pending → 改自动划页` 回退（run5 仍 1 ERR；非阻断，但真实 UI 路径 worth polish）。
- 自动化均分基线已抬到 4.3 档，**分数区分度变窄**——后续可考虑调整 `_score_run()` 权重以拉开 Happy/True 与 Normal 差距。

### 4.2 叙事体验 · **4.4 / 5**

**优点**

- **D3 刀垫全员触达**：信纸链均含「约定」，Gal 党（G1）、陪护读者（P2）等目标受众能看到中段情感预埋。
- **D10 双向 19/20**：觉醒/结局正文稳定出现「忘的，好像从来不只是我」「你也怕忘」等收网句；G1 Happy、C1 Happy、E1 True 均完整采样。
- D4 陌生化 telegraph 全员一致，中段「她像不认得你」的情感落差有落地。
- 信纸标题链完整：登门 → 雨天廊下 → 约定 → 失去 → 发现本子 → … → 树洞的本子 / 前夜，结构党（G2）可顺畅读表。

**问题**

- B1 双向=否属 **预期**（未跑满 D10 觉醒），不计入叙事缺陷。

### 4.3 交互与 UI · **4.2 / 5**

**优点**

- 篮子、WASD 走动、速通连点均未打穿状态机。
- G1/E1 真实划页 UI 可点选并收到小狸回话（「……划掉了。…——以后想不起来，别怪我。」）。
- 结局演职员表均可到达，harness 停在标题跳转前，未误触重开。

**问题**

- 划页 UI pending 回退（E1 run5 仍 1 ERR：`本子划掉 UI 后仍 pending，改自动划页`）说明 **StoryChoicePanel 与自动 resolve 的 handoff 仍偶发竞态**。
- 十八局仍走自动划页，真实 eviction 体验覆盖面偏窄（仅 G1/E1）。

### 4.4 LLM 陪伴 · **4.3 / 5**

**优点**

- **16/16 聊天成功**，零失败；取名后占位符正确（「……小白。好。我先念三遍。」）。
- C2「在吗」~400ms 有回复；延迟敏感画像未因等待弃坑（Bad 主因是低投入，非 API）。

**局限**

- 自动化仅发 **固定句**，未评 LLM 质量、OOC、引用纪律、stranger 口径。
- 11 局零聊天仍通关 → **「被记住/被认回」对沉默玩家可能体感偏弱**（设计取舍，非 bug）。

### 4.5 结局与重玩 · **4.5 / 5**

**优点**

- 四档结局（Bad / Normal / Happy / True）+ 赶走短终章，梯度清晰。
- **True 已实机验证**：E1 D6/D7 各喂 berry → `promise_fulfilled=true` → D10 `True门槛全过` → `ending_true`，4.8 分。
- W1 D8 meta 问句有回应，二周动机仍在。

**设计面**

- 除 E1 外无人走投喂线，True 仍 **高门槛、低自然到达率**——符合全收集定位，但需在 UI/引导上让「约定兑现」更可发现（F5 验收项）。
- Bad 占比 40%（含赶走）对「不夜坐、不聊天」玩家是 **有意反馈**，若希望沉默陪伴也有 Normal，需另开非聊天 recovery 途径（P3）。
