# 《河可松》· AI 伙伴长线设计方案

> 目标：从「会说话的 NPC」升级为**情感纽带与 AI 队友**——让玩家的行为真实沉淀进小狸，且**沉淀是可见的、有代价的、可复查的**。
>
> 本文只谈系统设计与落地顺序。叙事内核以 [`世界观设定.md`](世界观设定.md) 为准，正文以 [`十日版主路径正文.md`](十日版主路径正文.md) 为准。

---

## 〇、诊断：问题不在采集端，在回路

对现有代码做了三份盘点，结论如下。

### 采集端已经很完整，甚至过剩

`long_term_memory` 里已经有：五维人格向量 `persona`（warm/strict/active/optimistic/dependent，`game_state.gd:120-126`）、偏好 `prefs`、行为计数 `counters`、行为推断 `behavior_inferred`、关系信号 `relationship_signals`、锚点 `anchors`、日志 `day_journal`、聊天归档 `chat_archive`。`BehaviorCollector` 在种/收/买/卖/聊天时持续 drift 人格向量。

### 但一大半是「只写不读」

| 字段 | 状态 |
|------|------|
| `counters`（种收买卖计数） | 有写入，**全库无读取** |
| `player_busy`（玩家打断她的次数） | 有写入，**无读取** |
| `prefs.pace`（玩家说「慢慢来」） | 有写入，**无读取** |
| `behavior_inferred`（risk / coping） | 写入了，**不进 `memory_context`**，永远到不了 LLM |
| `persona.dependent` | 会 drift，**不进提示词**（`local_llm_server.py:370-372` 只取四维） |
| `memory_context.recent_journal` | 客户端组装了，**服务端不消费** |
| `story_boundaries.can_cite_episodic` | 打进 payload，**双端都没人读** |

### 玩家完全看不见因果

记忆面板「她的本子」只展示日志摘要、约定、锚点摘要、剧情碎片（`memory_panel.gd:34-75`）。人格向量、偏好、行为推断**一个都不展示**。亲密度变化也不提示——代码注释写明「改由小苗体现」（`main_ui.gd:1746-1747`），而小苗只是一段像素动画，**没有任何文字**（`relationship_sprout.gd:2-3`）。

更可惜的是：`MemoryService.build_citation_feedback()` 已经能生成「好像想起了……」这类反馈（`memory_service.gd:164-179`），但 `main_ui` **默认不展示**，只在 D6–D8 渗漏期或调试模式下才出现（`main_ui.gd:1766-1783`）。

> **诊断成立**：玩家做了很多事，数据全进了库，但既不影响她说什么，也不让玩家看见。输入没有可观测的输出——这正是「像 GALGAME」的定义。**要补的是回路的后半段，不是再加采集。**

### 主动搭话：一半是配额卡死，一半是写好了没接线

- 配额：经 `CompanionDirector` 的 LLM 主动口**每天最多 2 次**，且**每时段最多 1 次**（`game_state.gd:746-752`、`companion_director.gd:7-8`）。一天只有 180 秒（清晨 72 / 傍晚 36 / 夜晚 72）。
- 主线：D1–D9 每天恰好 1 个 beat，D10 无 beat 只有觉醒。
- **已写好但从未被调用的通道**：`session_start`（清晨开场 LLM）、`companion_react`（天气/里程碑反应）、`morning_sidewrite`（日初侧写）、`try_invite(as_remind=true)`（傍晚二次邀请）——服务端提示词全都写好了，客户端**一次都没发过**。

### 深层含义：暗线全挤在 D8–D10，且不可复查

传达「双向遗忘」的通道有碎片墙、本子、日志、觉醒、结局卡——**几乎全部集中在 D8 之后**。前七天玩家听到一句怪话就过去了，**没有任何地方沉淀**，所以到 D10 揭示时没有「我早该发现」，只有「你在说什么」。

## 一、统领性支点：把「两个本子」从道具升级为系统

不做散点修补。所有改动挂在一个支点上——**本子**。

选它是因为它一个物件同时解决五件事：

| 它天然是 | 因为 |
|----------|------|
| 长期记忆的**可见载体** | 玩家能翻，能看见她到底记住了什么 |
| 「记忆膨胀」的**玩法化解法** | 本子有页数上限，写满必须取舍 |
| 防幻觉的**结构保证** | LLM 只能引用本子上有的东西——本子就是 allowlist 的可视化 |
| 玩家渗透的**操作接口** | 玩家可以指定「把这件事写进去」 |
| 长期追求的**稀缺资源** | 页是有限的，所以「让她记住我这件事」变成一个目标 |

而它已经是故事内核（D8 两个本子），不需要新造设定。

## 二、系统设计

### 系统 A · 本子（The Notebook）

把不可见的 `anchors` 变成可翻、可操作、有代价的物件。

**A1 · 页可见**
`anchors` 上限已是 12（`memory_service.gd:8`）。把它渲染成 12 页可翻的本子，每页一条锚点，显示天数与摘要。玩家随时能确认「她现在记得的全部内容」。

**A2 · 玩家可以钉页**
新增交互：玩家在聊天里说「记住这个」，或在日志里点某条 → 该条 `importance` 拉满并置 `pinned=true`，永不被驱逐。
> 这是**玩家渗透最直接的接口**：她记住什么，由你决定。

**A3 · 写满了，当着你的面划掉一条**（核心情感装置）

现状是溢出后按 `anchor_score` 静默驱逐最低分（`memory_service.gd:227-256`）。**改成不静默**：

```
本子写满了。她翻来翻去，停在两页之间。
「……我得划掉一条。」
[ 她第一次教你认垄的那天 ]   [ 你说你不饿，她把红薯又拿了回去 ]
```

玩家选，或交给她按 `persona` 自己选（选择本身也是性格表达）。被划掉的条目**真的从 allowlist 移除**——之后她引用不到；玩家再提起，她会说「……我好像写过。划掉了。」

> 这一下同时是：记忆膨胀的技术解法、全游戏最强的情感时刻、以及「遗忘是有代价的选择而不是设定」的玩法化表达。**这是本方案里最值得做的一件事。**

**A4 · 三层记忆的引用纪律**（防幻觉的结构性保证）

| 层 | 内容 | 能否被当作事实引用 |
|----|------|--------------------|
| L1 工作记忆 | 今日 `today_chat_log` | 可以，仅限当天 |
| L2 情节记忆 | **本子的页**（`anchors`） | **可以，且只有这一层可以** |
| L3 语义记忆 | `persona_vector` / `prefs` / `behavior_inferred` | **绝对不可以，只影响语气** |

规则一句话：**她可以因为你一贯温柔而变得依赖你，但不能说「你上周三对我很温柔」——除非那件事在本子上有一页。**

这条纪律现在是缺的：`prefs` 直接以「玩家偏好」JSON 进了提示词（`local_llm_server.py:1481-1483`），LLM 完全可能把统计量说成具体事件。要在提示词里显式区分这两类信息，并在 `ResponseValidator` 加一条针对性检查。

### 系统 B · 性格漂移的可见化

**B1 · 加弹性回归**（长线一致性的关键）

现状：`persona_vector` 单向累加，clamp 到 [0,1]，**无衰减、无回归、跨周不清**（`game_state.gd:560-567`）。长线跑下去必然漂到 0 或 1 饱和，人设走形——这正是你说的 Consistency 挑战的根因。

改：每日向基线 0.5 做一次轻回归（如 `v += (0.5 - v) * 0.02`）。效果是**漂移需要持续行为维持**，一次性行为不会锁死人设。这是长线人格系统的标准解法，也让玩家感到「关系需要经营」。

**B2 · 让变化被说出来，但不用数值**

不做「好感度 +3」这类面板。改为：当某一维在 N 天内累计漂移超过阈值，触发一次 `persona_shift` 开口，走 LLM 并带上漂移方向。

关键是台词落点——**用一句她自己都没意识到的话**：

> 「我以前好像不这样。」

这一句同时是性格反馈**和**暗线埋点：她的「以前」是哪来的？

**B3 · 把 `dependent` 接进提示词**，把 `behavior_inferred` 接进 `memory_context`。已经在 drift 的维度不进提示词，等于白算。

---

### 系统 C · 把已写好的通道接上（成本最低，收益最快）

以下全部是**服务端提示词已写好、客户端只差一个 `request_event` 调用**的：

| 通道 | 接上之后 |
|------|----------|
| `session_start` | 每天清晨她说一句活的开场（现在是静态信纸文案） |
| `companion_react` | 天气突变、里程碑达成时她会反应（现在完全没接） |
| `try_invite(as_remind=true)` | 傍晚二次邀请，减少玩家错过 beat |
| **`build_citation_feedback` 全程显示** | **「她好像想起了什么」的可见证据**——现在只在 D6–D8 出现 |

最后一条尤其重要：这是「她真的记得你」最便宜的证明，代码已经写完了，只是被关着。

**同时改配额**：现在的「2 次/天、1 次/时段」是一刀切，把叙事口和生活口挤在同一个池子里。改为分频道：

| 频道 | 配额 |
|------|------|
| 叙事口（beat 邀请、渗漏） | 1–2 次/天，**优先级最高，不被生活口挤掉** |
| 生活口（闲聊、天气、里程碑） | 2–3 次/天，独立冷却 |
| 反应口（任务完成、投喂） | 不计入，仅冷却 |

---

### 系统 D · 旁白问题的答案：不要加旁白，要加「我的本子」

**明确建议：不要做全知旁白系统。**

理由有二。其一，这个故事的力量来自「我」的视角受限——我也在忘，我不知道自己在忘。全知旁白会把这一点说破。其二，世界观定稿写死了「遗忘成因不解释，留白即深度」；旁白天然倾向于解释，会把「人人都懂的痛」降格成「一个被讲明白的设定」。

**替代方案：把玩家自己的本子做成可翻的实体。**

D7 夜里玩家第一次写她（文案已有）、D8 她翻出玩家的本子（文案已有）——现在这两处只是叙述，没有实体。做成可翻之后：

1. 玩家能看见自己写了什么，且**可以选择写什么**（第二个渗透接口）
2. **从 D9 开始，玩家自己的本子会缺页**——对应世界观暗线⑤「我对时间感始终说不清」

玩家翻到自己写的东西缺了一页的那一刻，**不需要任何旁白**。这就是「被发现」而不是「被告知」。

---

### 系统 E · 暗线可复查化

世界观 §4 列了五条暗线埋点，现在只落实了一部分，而且**触发即消失**，玩家来不及意识到。

改：每次触发一条暗线（我脱口说出不该知道的事、我对时间感的破绽、系统口误），**自动在「我的本子」上留一行，标记为 `？`**。

D10 觉醒时，这些问号行**逐条亮起来**，与碎片墙并列。二周目回看时，本子上攒着的问号就是「我早该发现」的实证。

> 这才是「玩家理解不了深层含义」的正解：**不是加解释，是加可复查的痕迹。**

## 三、正面回应两个关键挑战

### 挑战一 · 长线人设一致性（Consistency）

| 手段 | 现状 | 方案 |
|------|------|------|
| 静态人设卡 | 有（`xiaoli_persona.json`） | 保持 |
| 阶段语气 | 有（stage_tone + D1–D3 相位覆盖） | 保持 |
| 输出校验 | 有（`ResponseValidator`：文艺腔/越界/事实锁） | 保持，加 L3 引用检查 |
| **人格向量回归** | **无**（单向漂移必然饱和） | **系统 B1** |
| **人设回归测试** | **无** | **见下** |
| `STORY_LLM_SPEECH_EVENTS` 强制 | **常量写了，无 guard** | 接上 |

**人设回归测试**是长线一致性唯一可靠的工程手段：把现有 `story_test_runner` 扩展成固定 seed 跑 N 轮对话，断言禁词表、句长、称呼规则、腹黑边界（不得出现「其实我记得」类表述）。每次改人设卡或提示词都跑一遍。**没有这层，任何提示词调整都是在盲改。**

### 挑战二 · 记忆膨胀导致的幻觉

| 手段 | 现状 | 方案 |
|------|------|------|
| 硬容量上限 | 有（anchors 12 / journal 7 / 周档 5） | 保持 |
| 低分驱逐 | 有（静默） | **改为当面划掉**（系统 A3） |
| **时间衰减** | **无**（只有硬 cap） | 在 `anchor_score` 加 recency 项，让旧页自然沉底 |
| 引用白名单 | 有（citable ≤3 条 + 双向 sanitize） | 保持 |
| **L3 不可引用纪律** | **无**（prefs 直接进提示词） | **系统 A4** |
| 服务端事实校验 | **无** | 客户端 `_sanitize_farm_hallucination` 已覆盖农事；扩展到记忆类断言 |

核心判断：**记忆膨胀的解法不是扩容，是让有界成为玩法。** 无限记忆必然导致幻觉；有界且**玩家参与取舍**的记忆，反而是这个故事最动人的部分——因为她的遗忘本来就是主题。

## 四、落地顺序

十日版仍要交付，按投入产出比排序。

| 阶段 | 内容 | 量级 | 解决什么 |
|------|------|------|----------|
| **P0** | 接线已写好的通道（`session_start` / `companion_react` / invite remind）；**citation feedback 全程显示**；分频道配额 | 小 | 主动搭话密度 + 「她记得我」的即时证据 |
| **P1** | 本子可翻 + 玩家钉页 + **写满时当面划掉** | 中 | 渗透接口 + 记忆膨胀 + 最强情感时刻 |
| **P2** | persona 弹性回归 + `dependent`/`behavior_inferred` 接进提示词 + 「我以前好像不这样」 | 小到中 | 长线一致性 + 性格可见 |
| **P3** | 「我的本子」实体化 + D9 起缺页 + 暗线问号复查 | 中 | 深层含义（替代旁白） |
| **P4** | 人设回归测试套件 | 小 | 长线一致性的工程保障 |

P0 一轮就能让「像 GALGAME」的观感明显改变，建议先做。P1 是这套方案的心脏。

## 五、明确不要做

- **不要加全知旁白**——会说破留白，违反世界观定稿的「不解释」原则。
- **不要做数值面板**（好感度 +3、性格雷达图）。一旦玩家开始盯数值，情感纽带就退化成刷分。反馈要走行为和台词。
- **不要给她无限记忆**。那是幻觉的来源，也会毁掉这个故事的主题。
- **不要让她「其实一直记得、只是装忘」**。见世界观 §0，这是产品命根。
- **不要再加新的采集字段**，直到现有的 `counters` / `player_busy` / `pace` / `behavior_inferred` 全部有下游消费为止。
