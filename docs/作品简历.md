# 《去狸的岛》· 简历用拆分

定位一句话（可当项目副标题）：

**在一部写死的十日剧情里，放进一个真会聊天的人。**

---

## 贴进简历：项目条目（推荐）

**《去狸的岛》**｜叙事游戏（Godot / 可通关）｜策划 · 系统设计

十日完整剧情游戏，内嵌一个能自然语言对话的 AI 同伴。主线（节点、选择、结局）全部写死，不交给模型即兴；聊天只决定她怎么说、会不会去浇田、本子上留下哪几页。断网仍可按剧本通关。

- **剧情层**：局内 10 天、多结局；每天有主节点；第五天去留分叉。
- **角色层**：唯一 NPC 小狸可打字聊天；答应浇田 / 过来会走进院子；记忆进有限本子（可钉、写满划掉），模型只能引用本子上有的内容。
- **接法**：剧本管「今天发生什么」，模型管「怎么说」；个性化用双档验收（认真聊 vs 几乎不聊，关键日台词必须不同）。

---

## 拆开写：两段（怕一条太挤时用）

**剧情（写死）**  
自己写了十天的主线：收留、约定、中段失忆、要不要继续留、终章。发生什么不看模型。玩家能通关，不是陪聊 Demo。

**人（真会聊）**  
狐狸小狸用大模型说话。玩家打字闲聊、拜托干活。她记得的事在本子上，玩家能看见、能取舍。第四天她会把你当陌生人——当天不把旧事传给模型，所以是真忘，不是装。

---

## 职责句（按实际岗位勾选用，不要全贴）

- 定十日结构与去留分叉，写节点正文与结局。
- 划分权限：剧本 / 记忆 / 对话，禁止模型改主线、自写长期记忆。
- 设计本子为记忆界面：有上限、可钉页、写满当面划掉。
- 规定聊天能驱动农事与走位，口头答应必须执行。
- 定个性化验收：聊与不聊，关键日必须听得出差别。

---

## 不要写进简历的

- 「创新点是遗忘」（那是剧情）。
- 「AI 伙伴 / LLM 驱动叙事」（像把编剧交给模型）。
- 引擎参数、云厂商、接口字段。
- 「用 Cursor / vibe coding 完成」（工具不是业绩）。
- 「独立实现全部系统 / 手写 X 万行」（经不起追问）。

---

## 若主要用 vibe coding 完成：简历写这些

写 **你定的规则、你验过的体验、你发出去的成品**。代码谁敲的，面试问到再诚实说：自己定需求与否决，生成稿逐条验收。

**可以写**

- 产品定位：写死的十日剧情 + 真会聊天的同伴，权限不交给模型。
- 你写的内容：十日结构、节点、去留、结局；本子上限 / 钉页 / 划掉；失忆日不传旧事。
- 你卡住的边界：模型不准改主线、不准自写长期记忆；嘴上答应的必须去浇田、过来。
- 你做过的验收：能通关；断网有剧本；认真聊和几乎不聊，关键日听得出差别；Web / Windows 可玩。

**不要写**

- 用了哪个编程助手、生成了多少文件。
- 把每个子系统都写成「我实现了」。
- 把遗忘当技术创新。

**面试备一句**

「实现上大量用生成式工具。我负责的是：故事和权限怎么分、什么算做完、玩起来对不对。生成出来的东西，不符合这三条就改掉。」
