## 1. 这是什么项目

Godot 4.7 俯视像素农场 + AI 狐狸「小狸」。产品形态是 **10 日完整可通关**（不是 Demo、不是 35 日五周）。

一句话：玩家独居河边农场，收留会周期性失忆的小狸；这十天是她最后一个轮回。D10 揭晓忘的也不只是她。谁都好不了，但能从空白里把对方找回来。

核心体验只有三件事：被记住 → 被忘记 → 被认回。种田是生活质感，不是经营目标。

## 2. 铁律（违反即错）

叙事（定稿 0.5 节，最高优先）：

1. **不引入第三个角色**（无阿嬷 / 病房 / 逝去伙伴）。
2. **小狸的失忆是真的**。严禁写成「其实一直记得、只是装忘」。
3. **双向遗忘**：玩家「我」在轮与轮之间也会忘；此真相 **D10 才收网**，此前只埋暗线。
4. **没有治愈、没有 New Game+ / 通关后再开一轮**。True/Happy 是「会忘的前提下仍留下锚」。
5. 对外只说「第几天」，不对玩家说「第几周 / 第五周 / 35 日」。
6. LLM **不改写主线、不自写长期记忆**。游戏状态是事实，LLM 只负责怎么说。
7. **剧情搭话须与 LLM 联调、统一口径**：凡小狸主动开口且与当日叙事相关（邀请、渗漏、闲聊、信纸后搭话、上线问候、玩家聊天等），**必须**走 LLM，且 payload 须带齐 `story_context` + `beat_context`（含 `variant_id` / `profile` / `invite_tone` / `invite_goal`）。信纸正文以 `story_nodes.json` 为准，LLM 只铺垫不念稿；**禁止**客户端另写与当日节点/亲密度档矛盾的固定台词。仅「追跑短句」等纯 UI 提示可本地兜底。改节点变体或 invite 时，**同步** `tools/local_llm_server.py` 与 `cloudrun/xiaoli-api/tools/local_llm_server.py`。完整 payload 规范见 **策划 §4.5.5**。

地图 / 范围（本迭代明确不做）：

- 不要第二张地图、室内、新作物种类、第二 NPC。
- 不要恢复中间那两垄「工作田」。可种的田 **只有最右边围栏里的三垄**。

### 5.3 视觉层第三轮：「太丑」返工（2026-08-17 深夜）

用户看完第二轮只回了一句「先改美观，太丑了」。这一轮找到的根因不是构图，是**像素倍率是乱的**，另外三件是配色和摆法。

**倍率取整（最要紧的一条）**。地面各层是 `scale 2`，一个源像素正好占 2 个屏幕像素。可摆设当时是 `2.0/2.2/2.3/2.4/2.6/2.9`、老屋 `3.2`、树洞 `3.3` 混着来。在 nearest 过滤下非整数倍会让**同一张贴图里**有的源像素占 2px、有的占 3px——老屋 75 列源像素里有 15 列宽 4px、60 列宽 3px，边缘参差，整个场景发糊显廉价。现在 `yard_dress.gd` 立了三条硬规矩：**缩放只允许 1/2/3**（大件用 3 当近景）、**坐标必须偶数**（对齐地面的 2px 像素格）、`offset` 必须取整（贴图宽是奇数时 `-w/2` 会落在 .5 上，半像素采样直接发虚）。`_snap_sprites()` 会连烘进场景的老件一起收拾，第一次跑收整了 **55** 件。高倍镜头复核过：砖缝、屋檐板、窗框现在颗粒一致。

**配色定主色**。这套树素材有四个色系：深绿（tree_01/02/03/13）、蓝（08~12）、柠檬绿（04/30/31）、洋红（29/32）。上一轮南边树线把深绿+柠檬绿+蓝混着摆，所以那条线是花的。现在**主色只用深绿**；蓝只留在最西边两丛，跟原有的西南蓝绿林接上；**柠檬绿全院只留一株**（ClumpD2）当高光；院心那株粉樱因此成为唯一的高饱和色。原来紧挨粉樱的柠檬绿 tree_31 换成了深绿，别抢它。

**不许孤件**。一个桶、一块石、一丛草各自摊在草地上是最容易露馅的摆法。现在每处至少 2~4 件互相压着、脚位错开 8~16px。南缘也从 18 株等距单排（一排棒棒糖）改成 **8 处不规则树丛**：每丛 1 大压 2 小、丛内间距只 30~40px 让树冠重叠成一团，丛间拉到 160~200px，1012~1180 留一处豁口。每丛的「大株」在 tree_13/02 之间轮换，别一个剪影重复八次。另外屋前原本左右各插一株**一模一样**的 tree_01，近乎对称，西侧已换成 tree_03 并错开 y；柴堆往下挪了 24px，之前木头顶端戳进墙里。

**草坪补质感**。`analyze_tilemap` 直接给了客观证据：`草地` 层 **82% 的格子是同一个瓦片 `(21,25)`**，工具自己报 `low-variety` 警告——「一块绿板子」不是主观感受。现在 `_scatter_meadow_tufts()` 按 15 处椭圆团撒草簇（中心密度约 800‰、边缘按 `1 - 0.75·dist` 递减，共 163 格）。**三重护栏**保证安全：`草地` 层必须正好是纯草 + `河流树木家园` 和 `沙地` 层为空 + `地面细节` 层为空，这样绝不会盖到路面、水面和底图已有装饰。

**踩到并修掉的两个坑**：

1. `TUFTS` 那 5 个瓦片里，`(22,4)` 和 `(23,4)` 是**暗红褐色的菇/枯堆**，不是草。第一版撒完草坪像撒了一片污渍——这同时是上一版幽灵垄一直看着脏的原因（用的是同一组瓦片）。现在 `TUFTS` 只留绿的 `(17,2)(19,4)(20,4)`，旧田要的褐色由 `RidgeMud*` 那几张泥贴图给。
2. 5.2 里的「断篱桩 `(44,6)`」是**误判**。图集列 44 的第 3/6/9/12 行是**同一个小植物的四种配色**（9 绿、12 洋红、6 红粉），`(44,6)` 是红粉小叶子，既没起到标记垄端的作用又添色噪。现在改用三块界石 Sprite（`RidgeMarkW1/W2/E`，rock_09/rock_28）压在三条垄的两端——人辨认「这里曾是一块田」靠外框和垄端，不靠垄的中段。

**识别瓦片外观的可靠办法**（下次别再猜）：`find_tiles` 的 `query` 参数不做过滤，返回的总是同一张 128 格总表，没法定位；`render_tilemap_image` 的 `cell_size` 也不生效，永远按 16px 原生输出。有效的做法是**在已知内容的格子上渲染 1×1 区域**——出来是张 16×16 小图，虽小但判断颜色足够，还能并发一次问五个。

**补做：房子左边 + 商店上边**（用户追问「这两处你都没修改吗」，确实漏了）。

*房子左边*是全图最像没做完的一块：底图在这儿留了两条**断头石板路**（竖的到 world y≈448 停；L 形的竖臂上端到 y≈495 停、横臂东端到 x≈715 停），外加两块**硬直角**的深绿灌木方块（world 96\~224 / 352\~448）和格子纹补丁（384\~512 / 352\~480），再加三个蓝陶罐、告示牌、两根杆子，各自孤立散在一大片平草上。断头路一律**用树丛收掉** —— 路「消失进树丛」读成路继续往前，「突然停住」才读成没做完；方块沿用压水塘直角那一招，在角上和长边压植被。另外在房子西北那片空草坪补了一丛，别让房子孤零零悬着；告示牌下边补一对，其中一株用蓝色接西南那片蓝绿林（这一带偏西，允许出现蓝；靠房子那侧仍然只用深绿）。

*商店上边*原本是屋顶和地图上边之间约 220×170 的一条空档，商店背面什么都没有。补了两件：三丛树把**北缘里面那排**接下去（1290\~1330 留豁口），以及商店背面堆的货箱+桶+干草——它是个做买卖的地方，后头本来该有箱有桶。

**这里踩到一个读图的坑**：`河流树木家园` 层的 `minY` 是 **-1**，贴边那排北缘树画在 **cell y=-1**。我一开始按 y≥0 渲染，看不见它，于是误判「北缘树带缺了一整段」。实际是**两排**：贴边那排在 y=-1，里面那排在 world y 30\~190、但到 world x≈1050 就断了。所以补的是里面那排，脚位定在 y 136\~176 让树冠和贴边那排咬住、中间不留草缝，下面又给商店屋顶（y=262 起）留出空带。以后读这张图记得把 y=-1 算进去。

这一轮**没动、留给后面**的四件：`家` 图层仍是 `scale 2.5`（非整数，北边那几栈建筑还在发糊；改成 2 会让它们缩小并错位到别层画好的石头基座之外，风险大）；底图自带的**洋红树**约九株散在地图外圈（它们框住了中间的院子，算原作风格，但确实把粉樱的「唯一」稀释了）；西边两条**断头石板路**；底图那几块**带九宫格收边的方形草地台**（`(20..22, 24..26)`，硬直角——西边那两块已在角上压了植被，别处还没）。

### 5.4 搬家 + 主街重修（2026-08-18）

用户要求三件：老屋搬到左上角、周围重排（「太杂乱」）、主街修缮成「家↔商店↔农田↔廊下互通、偏宽、不错综复杂」。

**先说读图踩的坑：旧路网画在 `草地` 层，不是 `河流树木家园` 层。** 我一开始找错层白绕一圈。`草地` 层上凡是 `atlas_x <= 11` 的格子都属于路面/土路的自动拼接块，纯草块和四周收边瓦片全在 20\~22 列。所以「先把全图 `atlas_x<=11` 刷回纯草块 `source 0 / (21,25)`，再画新路」既清得干净、重跑也幂等。**刷回去只能用 `set_cell`，不能用 terrain connect** —— 理由同 5.1，terrain 0 的中心块是米色土。

**路网只要一条直街，不要网。** 量完坐标发现根本不用岔道：商店摊位底边在 world y 388、廊下木地顶边在 572，一北一南正好夹住 y 416\~544 这条带。所以主街就走这一条四格宽的直干（`ROAD_RECTS` 第一条，cells x7\~49 / y13\~16），商店直接开在路北、廊下直接开在路南，只留一条支路拐上西北角的新家，东端一个落脚坪穿田北围栏缺口下田。四处目的地各只有一个入口，动线一眼读得完。

**凹角交给 `set_cells_terrain_connect`。** 丁字口内侧的凹角手摆九宫格表达不出来，图集第 4\~7 列那几张就是干这个的。底图那团旧迷宫当年也是这么刷的。实测 204 格全部和计划一致，凹角自动接对。

**搬家要同步改三处，缺一处就不一致**：`yard_dress.gd` 的 `HOUSE_POS`、场景里的「人」标记（`farm_world._player_spawn_position` 直接读它当出生点）、`farm_setdress.gd` 的 `POS_HOME` 常量。**`companion_agent.gd` 建「旧屋门口」POI 时读的是那个常量而不是标记点**，所以只改标记点，小狸眼里的「家」会留在原地。新址 `(272, 304)`，贴图 76×48 / scale 3 / offset (-38,-42)，占 world x 158\~386 / y 178\~322。支路最上一行藏在贴图底下，路口才不露收尾盖。

**清杂物**（`HOME_CLEAR_RECTS`，11 个矩形）。新屋落到西北角后，这一带的底图杂物正好压在屋子、门前路和主街上：两条断头石板路、硬直角深绿灌木方块、三个蓝陶罐、两根杆子、告示牌、格子石板庭院及收边。用户说「太杂乱」，所以整片清掉，绿化改由 `西院` 组的树丛重新做。5.3 那一组「给丑东西收边」的摆件因此整组作废（收边对象没了）。另外顺手清掉 `(17,11)` 那块 2×2 亮绿草台 —— 它贴在主街北肩上，比周围草地亮一截又是方的，旧路乱的时候混在杂物里看不出来，路一收拾干净就成了全图最显眼的补丁。

**验收时逮到的三处「东西站在路上」**：

1. `路边` 那丛「廊下到田」的补树脚位在 y 592\~620，但 **`tree_13` 放大 3 倍树冠有 132px 高**，顶到 y 460，整丛盖在主街路面上，看着像树从石板缝里长出来，还把刚拓宽的路又挡窄回去。已下移到 y 684\~700。**摆件按脚底对齐画，判断「会不会压路」要算 `脚位 − 树冠高`，不能只看脚位。** 全图按这个算法过了一遍，主街带（y 416\~544）内已无任何摆件脚位；靠路的件（`路边` 石头花盆、`院心` 粉樱、`西院` 口袋丛）脚位一律 ≤410，即贴着路北肩往上长。
2. 东北角底图那片砾石（`(2,36)`，我先前误判成河水）有条尾巴从院子往南伸到 row 14 就停，而落脚坪从 row 16 起，**中间空一格草，两片石头差一格没接上** —— 最难看的那种接缝。尾巴不通向四处目的地里的任何一处，清掉；砾石院子和它西南角那口井（`(23,56)/(23,57)`，cell 45 / rows 11\~12）留着 —— 院子紧邻商店读成「商店的院子」，井正好落在主街北肩上。尾巴一清院子东南角露成裸直角，补两棵深绿探过院边压住。
3. `西院` 那丛口袋树（`tree_13` scale 3，横跨 world 404\~536）压在 `屋前` 东侧两个花盆（372、416）上，花盆整个被树冠吃掉，门口挤成一堵植被墙。已把门边组收紧到贴着门（x 346\~444）、口袋丛整体东移收成一丛（490\~632）。

**主街北肩的节奏**（长边 900px 全空会假，全铺又成绿墙，所以要断续、疏密不等距）：门边组 346\~444 | 空 46 | 口袋丛 490\~632 | 空 46 | 粉樱那组 678\~910 | 空 85 | 石头对 995\~1050 | 空 195 | 商店门前 1245\~1305。

F5 实测：0 报错，玩家出生在门口台阶上正对路口，房子在左上角，一条宽直石板街往东串起商店、廊下、田。

`yard_dress.gd` 的摆设现在分十一组：`屋前 廊下 院心 树洞 旧田 草甸 路边 塘边 田东 商店后 西院`，共 134 件。组名列在 `GROUP_NAMES`，重跑时按组整个删掉再建，所以**加组必须同时加进 `GROUP_NAMES`**，否则旧组会留在场景里变成重影。

### 5.5 院子碰撞（2026-08-18）

用户要求给廊下、`河流树木家园`、树洞加碰撞。**不能整层刷实心**：那层 526 格里一大半是草角楔子、花、菌子，逐格碰撞会在草坪上撞看不见的墙，斜岸也会变成 32px 锯齿。走的是交接里说的便宜办法：`FarmMap/WorldCollision`（`StaticBody2D`，layer 1）下手摆矩形。

只挡真正实心的：廊下北栏杆 + 三根柱子（木地可走，从南面进）、树洞树干（`HollowTree` 脚位 `(1152,304)`，交互距离 96 仍够）、水塘、北缘木栏、东北岩岸、田东那条河、田围栏（北面 `x51~52` 缺口留着进田）、以及该层上商店摊位那块底图。草簇、花、田垄都不挡。

光挂静态体本来不够：`player.tscn` 原先 `collision_layer/mask = 0` 且**没有** `CollisionShape2D`，`move_and_slide` 撞不到任何东西。已补 10×8 的脚底矩形（`_ready` 里 `scale=2`，世界里大约 20×16），layer/mask 走默认第 1 层。

F5 实测：从门口往南走到水塘北沿 `y=678` 停住（没有碰撞会滑到 walk_bounds 底边 ~1076）；往东走到田西围栏 `x=1434` 停住。小狸是 `Area2D`，不会被这些墙挡住。老屋本体这轮没加。

改碰撞：在编辑器里拖 `WorldCollision` 下那些 `CollisionShape2D`，不要重跑 `yard_dress.tscn`（会覆盖手改的摆设）。

改院子直接在编辑器里拖这些 Sprite。`tools/yard_dress.tscn` 是当时的一次性摆放脚本（可重跑，但**会覆盖手改**）；`tools/yard_shot.tscn` 拉远拍整院日景用来自查，`tools/asset_sheet.tscn` 把素材目录排成带文件名的网格。

相机 / 走路：范围取「草地」`used_rect` 转世界坐标，`set_walk_bounds(map_rect.grow(-12))`。聊天 UI 会挡住下半屏，那是说话时的 UI，不是走路范围 bug。

标题镜头焦点：`title_screen.gd` `WORLD_FOCUS = (1080, 500)`。

最近玩家反馈：南面广场凌乱 → 已清成草地。若 F5 后南面仍有雕像/断头路，再查 `河流树木家园` 是否被 punch 漏掉，或 `user://` 没跑到最新脚本。

## 7. 改代码时的习惯

- 文案改 `config/story_nodes.json`（客户端 payload 下发；云上 `cloudrun/.../config` 对运行中的 Godot **不自动生效**）。
- 院子改 `farm_setdress.gd` + 必要时 `farm_world.gd`。改完 **F5**，不要只看编辑器。
- 日历/结局改 autoload 后跑 `story_test_runner`。
- **剧情搭话 / LLM payload**：见铁律 §2-7 与 **`docs/十日版策划定稿.md` §4.5.5**（`beat_context` 字段、变体同步、禁止客户端另写矛盾台词）。
- 改 `local_llm_server.py` 时 **同步** `cloudrun/xiaoli-api/tools/local_llm_server.py`，并 **重新部署 Cloud Run**。
- 加节点变体文案前先看 **`docs/十日版主路径正文.md`** 文笔；mid 档勿写成 warm/cold 折中腔。
- mid profile 联调：`py -3 tools/test_mid_profile_llm.py`（本地 `_beat_context_line` + 可选 Cloud Run D2 邀请）。
- 中文回复对用户；少写新 markdown，除非用户要文档。
- 不要把 `build/web` 加回 Git。导出用 `deploy_web.bat`（里面 Godot 路径写死为旧电脑 `E:\Godot_v4.7-stable_win64.exe\...`，新电脑要改）。
