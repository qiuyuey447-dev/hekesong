## 一、项目概述

### 1.1 一句话介绍

《河可松》是一款 **星露谷风格俯视角家园 Demo**，玩家与 AI 动物伙伴「小狸」在日常派活与自由聊天中建立长期情感纽带。小狸会记住共同经历、保持性格一致，并在协作中给出个性化反馈。

### 1.2 核心主张

> 我们不是在做「更像人的 NPC」，而是在做 **「会记住你、会随你成长、值得每天回来看一眼的 AI 伙伴」**。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **派活做骨架** | 游戏有可玩的日常循环，不是纯聊天窗口 |
| **聊天做灵魂** | 情感连接来自被记住的协作与对话，不是挂机收菜 |
| **事实与表达分离** | 任务结果由游戏状态决定，AI 只负责「怎么说」 |
| **小而深** | 单场景、单伙伴、单条关系线，把 AI 工程化做透 |

### 1.4 对标与差异

| 参照 | 借鉴点 | 本作差异 |
|------|--------|----------|
| 动物森友会 | 日常回访、动物伙伴、轻量家园 | 引入 AI 长期记忆与动态对话 |
| 星露谷物语 | 俯视角像素、农田、固定镜头 | 核心卖点是 AI 情感而非经营规模 |
| 乙女 / 养成 | 关系阶段、专属称呼、promise | 非恋爱向，偏治愈协作 |

## 二、目标用户与使用场景

### 2.1 目标用户

- **主要**：18–30 岁，喜欢 cozy 游戏、养成、AI 互动的玩家  
- **次要**：关注 AI NPC、大模型应用的游戏行业评委与开发者  

### 2.2 核心使用场景

- **每日 3–5 分钟**：登录 → 小狸问候 → 派活 → 收工反馈 → 聊几句  
- **连续 7 天体验**（Demo / 测试）：验证记忆召回、关系成长、promise 兑现  
- **参赛演示 10–15 分钟**：Day1 → Day7 压缩流程 + 记忆面板对比实验

## 三、世界观与角色

### 3.1 世界观（轻量）

玩家拥有一块小家园：门外是农田，门内是起居空间。没有复杂主线，重点是 **与小狸一起把家慢慢过好**。

### 3.2 唯一伙伴：小狸

| 属性 | 设定 |
|------|------|
| **物种** | 狐狸 |
| **性格** | 认真、温和、轻微操心，像靠谱的小管家 |
| **说话风格** | 短句、条理清晰，偶尔唠叨，不用网络梗 |
| **禁止行为** | 油腻、PUA、捏造未发生的事、突然 OOC |
| **玩家可定制** | 给小狸起昵称；关系加深后解锁专属称呼 |

**开发任务**：B2 编写完整 Persona Card（含 3 阶段语气模板）

### 3.3 关系阶段

| 阶段 | 解锁条件 | 表现变化 | 任务 ID |
|------|----------|----------|---------|
| **初识** | Day 1 | 礼貌、稍拘谨，称呼「你」 | A7 ✅ |
| **熟悉** | 亲密度 ≥ 30 且 Day ≥ 3 | 主动提醒、使用昵称、给建议 | A7 ✅ |
| **羁绊** | 亲密度 ≥ 60 且完成 1 次 promise | 引用共同经历、语气更暖但仍克制 | D5～D7 ⬜ |

> **一致性规则**：关系阶段只改变 **语气强度**，不改变 **本质性格**（小狸再熟也不会变成话痨或冷漠）。

## 四、核心玩法循环

### 4.1 主循环（每日）

```
登录                    ← B4 session_start（⬜ 待接 GameNPC）
  → 小狸主动问候（引用上次事件 / 记忆）
  → 查看状态（天数、亲密度、心情）        ← A6 ✅
  → 选择派活（浇水 / 外出采集）          ← A4、A5 ✅
  → 等待完成（可快进）
  → 小狸基于任务结果反馈                  ← B5 task_complete（⬜）
  → 可选：自由聊天                        ← B6 player_chat（⬜）
  → 小狸写入今日日记（后台）              ← C6 day_end（⬜）
退出
```

### 4.2 派活系统（骨架）

| 任务 | 时长（Demo） | 触发方式 | 游戏产出 | AI 参与点 | 任务 ID |
|------|--------------|----------|----------|-----------|---------|
| **浇水** | 约 5 秒 | 点击农田 | 该格田变为「已浇」；亲密度 +3，默契 +2 | 完成语、引用玩家偏好 | A4 ✅ |
| **外出采集** | 约 8 秒 | 点击「出门」门 | 获得材料（占位）；亲密度 +2，默契 +1 | 带回见闻、情感反馈 | A5 ✅ |

**设计要点**：
- 每块田 **每天只能浇一次**，跨天重置（A8 ✅）  
- 任务进行中不可开始新任务、不可「下一天」  
- Demo 提供 **快进** 按钮，方便录屏与测试  

### 4.3 聊天系统（灵魂）

| 阶段 | 状态 | 说明 |
|------|------|------|
| 占位版 | ✅ A9 | 关键词匹配回复，用于玩法验证 |
| GameNPC 版 | ⬜ B6 | 对话引用记忆，不编造任务结果 |
| Fallback | ⬜ B7 | API 失败时 10 条模板保底 |

- 聊天增加少量亲密度（+1 / 次），但 **主要成长来自派活协作**  

### 4.4 养成数值

| 属性 | 含义 | 主要来源 | 任务 ID |
|------|------|----------|---------|
| **亲密度** | 情感深度 | 派活、聊天、跨天登录 | A6 ✅ |
| **默契值** | 协作习惯 | 连续完成同类派活 | A6 ✅ |
| **心情** | 当日状态 | 登录 + 派活成功；长期不登录缓慢下降 | A6 ✅ |
| **天数** | 时间轴 | 「下一天」按钮（Demo 手动跨天） | A8 ✅ |

## 六、AI 系统设计（赛题核心）

### 6.1 设计目标

1. **长期记忆**：跨天引用关键事件（赛题挑战：记忆膨胀）  
2. **性格一致**：长线交互不 OOC（赛题挑战：Consistency）  
3. **低幻觉**：不编造未发生的任务与对话  

### 6.2 架构分层

```
玩家输入 / 游戏事件
		↓
   事件抽取层（结构化）              ← C1 ⬜
		↓
   记忆系统（分层存储 + Top-K 检索）  ← C2、C3 ⬜
		↓
   人设 + 关系状态机                 ← B2、A7 ✅（数值侧）
		↓
   对话 / 反馈生成（GameNPC）        ← B3～B6 ⬜
		↓
   一致性校验层                     ← C7 ⬜
		↓
   输出到 UI / 游戏
```

### 6.3 记忆分类

| 类型 | 内容示例 | 写入规则 | 任务 ID |
|------|----------|----------|---------|
| **情节记忆** | 「D3 玩家说喜欢慢慢来」 | 每轮抽 0–2 条，importance < 0.4 丢弃 | C1 ⬜ |
| **语义记忆** | 「偏好：慢节奏、先浇水再聊」 | 同类行为合并为趋势 | C1 ⬜ |
| **关系记忆** | 亲密度 62、阶段「熟悉」、昵称 | 随数值自动更新 | C2 ⬜ |
| **Promise** | 「田好了告诉我」 | 显式标记，未完成前优先召回 | C2、D5 ⬜ |

### 6.4 防幻觉机制（Cited Response）

| 规则 | 说明 | 任务 ID |
|------|------|---------|
| **Fact Lock** | 浇了几块田、采了多少 → 必须来自 `game_facts` | C4 ⬜ |
| **Cited Memory** | 「你上次说过…」必须绑定 `memory_id` | C5 ⬜ |
| **无 ID 不说** | 检索不到的记忆，禁止假装记得 | C5 ⬜ |
| **校验重写** | 违背人设 / 捏造事件 → fallback 模板 | C7、B7 ⬜ |

### 6.5 与 GameNPC 的事件协议

| 事件 | 触发时机 | 任务 ID | 状态 |
|------|----------|---------|------|
| `session_start` | 登录问候 | B4 | ⬜ |
| `task_assign` | 确认派活 | — | ⬜（P1） |
| `task_complete` | 任务结束（携带 game_facts） | B5 | ⬜ |
| `player_chat` | 自由聊天 | B6 | ⬜ |
| `day_end` | 跨天 / 退出，写日记 | C6 | ⬜ |

**示例 payload**：

```json
{
  "event": "task_complete",
  "companion_id": "xiaoli",
  "game_facts": {
	"task": "water",
	"plot_id": 3,
	"game_day": 2
  },
  "relationship": { "affection": 15, "stage": "stranger" }
}
```

**计划实现**：`scripts/autoload/npc_bridge.gd`（B3）

### 6.6 一致性保障

1. **Persona Card（硬约束）**：固定 300–500 tokens 人设，不变（B2 ⬜）  
2. **关系软约束**：阶段只改语气，不改性格（A7 ✅）  
3. **日记锚点**：每日 50 字结构化日记，次日读最近 3 条（C6 ⬜）  
4. **OOC 反馈（P2）**：玩家点「不像 TA」→ 记录负样本

## 十二、创新点（答辩用）

1. **Emotional Task Loop** — 派活不是挂机，任务事实进入记忆，聊天引用这些事实  
2. **Fact–Expression Split** — 游戏状态是铁律，AI 是表达层，架构上抑制幻觉  
3. **Cited Companion Dialogue** — 对话可溯源（memory_id），回应记忆膨胀挑战  
4. **Growth-bound Persona** — 关系阶段改语气不改性格，回应 Consistency 挑战
